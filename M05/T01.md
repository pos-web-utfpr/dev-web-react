# Desenvolvimento de Aplicações Web Dinâmicas e Interativas

## Módulo 5: Boas Práticas e Testes Automatizados

**Objetivo de Aprendizagem**: Aprimorar a qualidade do código e garantir a confiabilidade através da adoção de boas práticas de desenvolvimento e testes automatizados.

## Tópico 1: Boas Práticas para a Construção de Componentes Reutilizáveis

- Isolamento de lógica:
  - Componentes
  - Eventos como props
  - Hooks
  - Helpers
- Padronização de nomenclaturas

## Prompts da Aula

**Prompt 1**:

```markdown
Vamos PLANEJAR a refatoração da página de produtos (`pages/Produtos.tsx`) e aplicar nela boas práticas com react. A tela está muito carregada, mistura lógica de negocio com UI. O componente principal também é muito grande e confuso, vamos criar sub-componentes e organizar a estrutura da tela.

Me ajude a planejar isso, vamos isolar em componentes tudo o que for possível, separar a lógica da paginação, separar a seção "featured", na tabela separar a header das linhas. Se você perceber outros detalhes desta tela que podem ser melhorados, também inclua no plano.

Funções helpers devem ser movidas para uma pasta src/helpers.
```

**Prompt 2**:

```markdown
Gere um planejamento para refatorar as outras telas da aplicação, seguindo os mesmos princípios.

Formulários devem ser isolados em um componente específico, ex: LoginForm. O event submit deve ser uma prop do componente (tratamento no pai).

Sempre que possível, crie um custom hook para gerenciar as ações da página (fetch de dados, envio de dados por chamadas de API, etc). Idealmente, a tela deve se concentrar em renderizar o hook e não tratar a lógica de negócio. Os componentes filhos devem ao serem usados na tela pai devem favorecer a boa legibilidade da estrutura da tela.
```

**Prompt 3**:

```markdown
Agora vamos trabalhar na padronização da nomenclatura dos arquivos da aplicação. Temos mistura de kebab-case com CamelCase, padronize tudo com kebab-case, mas atenção: os nomes dos componentes react devem permanecer CamelCase.

Durante esta etapa, padronize o idioma do código, vamos usar inglês no nome dos arquivos, nomes de componentes, props, helpers, etc. Mantenha as strings (textos de interface) já existentes na aplicação em português.
```
