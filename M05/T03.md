# Desenvolvimento de Aplicações Web Dinâmicas e Interativas

## Módulo 5: Boas Práticas e Testes Automatizados

**Objetivo de Aprendizagem**: Aprimorar a qualidade do código e garantir a confiabilidade através da adoção de boas práticas de desenvolvimento e testes automatizados.

## Tópico 3: Testes E2E

- Instalação e configuração do Playwright
- O que testar? Fluxos!
- Navegação, preenchimento de formulários, asserções visuais
- Screenshots e relatórios de testes
- Fechamento: testes unitários vs. E2E, qual usar? Ambos!

## Prompts da Aula

1. **Instalação e Configuração do Playwright com Backend Local (ServeRest):**

```markdown
Instale e configure o Playwright no projeto (`@playwright/test`).

A API que roda no frontend (URL online) será considerada ambiente de produção, portanto, ao utilizar testes E2E vamos subir localmente a API ServeRest (`supermercado/backend/ServeRest`).

Para garantir o isolamento e determinismo dos testes, crie um script pré-execução (ex: `scripts/reset-db.js` ou utilizando o hook `globalSetup` do Playwright) que zere/resete os arquivos de dados do ServeRest (`supermercado/backend/ServeRest/src/data/*.db`) para um estado inicial limpo antes da execução da suíte de testes.

Configure o `playwright.config.ts` para definir a `baseURL`, os navegadores para testes, a execução prévia do script de reset do banco e a execução automatizada dos servidores locais (webServer) para rodar o backend ServeRest e o frontend durante os testes E2E.
```

2. **Criação de Testes E2E para Fluxos do Usuário:**

```markdown
Crie suítes de testes E2E utilizando Playwright para cobrir os fluxos principais da aplicação (como login, navegação entre páginas e cadastro/preenchimento de formulários).

Implemente ações de navegação, preenchimento de campos de formulários e validações de interface com asserções visuais e de estado (`toBeVisible`, `toHaveText`, `toHaveURL`).
```

3. **Execução, Screenshots, Relatórios e Estratégia de Testes (Unit vs. E2E):**

```markdown
Configure no `package.json` os scripts de execução do Playwright em modo headless, UI interativa e geração de relatórios de testes (com captura de screenshots em caso de falha).

Organize a estratégia de testes do projeto documentando quando utilizar testes unitários (para funções isoladas, helpers, hooks e componentes) vs. testes E2E (para fluxos completos da aplicação integrados ao ServeRest local), demonstrando por que ambos devem ser usados em conjunto.
```
