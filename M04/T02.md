### Prompt 1: Interceptor de Autenticação com Axios e Gerenciamento do Token (Login e Logout)

```markdown
Vamos PLANEJAR a integração da autenticação com a API da ServeRest utilizando interceptores da Axios e gerenciar o ciclo de vida do token JWT (incluindo a limpeza no logout).

Atue como um desenvolvedor Front-end especialista em React. Preciso que você configure o envio automático do token de autenticação em todas as requisições HTTP e garanta que o logout remova o token armazenado.

Requisitos:

1. **Armazenamento do Token no Login**:
   - Na página ou serviço de login (`Login.tsx`), ao autenticar com sucesso contra a API da ServeRest (`POST /login`), armazene o token de autorização recebido na resposta no `localStorage` (ex: `localStorage.setItem('token', response.data.authorization)`).

2. **Interceptor de Requisição (Request Interceptor)**:
   - No arquivo `src/services/api.ts`, adicione um interceptor de requisição via `api.interceptors.request.use()`.
   - O interceptor deve verificar se existe um token salvo no `localStorage`.
   - Caso exista, inclua-o nos cabeçalhos da requisição através do header `authorization` (padrão esperado pela ServeRest).

3. **Interceptor de Resposta (Response Interceptor / Tratamento de 401)**:
   - Adicione um interceptor de resposta via `api.interceptors.response.use()`.
   - Se a API retornar erro de não autorizado (status `401` ou `403`), remova o token do `localStorage` (`localStorage.removeItem('token')`) e redirecione o usuário para a rota de login (`/login`).

4. **Remoção do Token no Logout**:
   - Atualize a função de logout (no `RootLayout.tsx` ou componente responsável).
   - Ao clicar em "Sair", limpe explicitamente o token do `localStorage` (`localStorage.removeItem('token')`) antes de redirecionar para a tela de `/login`.
```

### Prompt 2: Tratamento Global de Erros com Interceptor e Notificações (Mantine)

```markdown
Vamos PLANEJAR o tratamento global de erros HTTP na aplicação utilizando o interceptor de resposta da Axios e a biblioteca de notificações do Mantine (`@mantine/notifications`).

Atue como um desenvolvedor Front-end especialista em React. Preciso que você configure um interceptor de resposta global para capturar falhas nas requisições à API ServeRest e exibir alertas amigáveis para o usuário.

Requisitos:

1. **Interceptor de Resposta (Response Interceptor)**:
   - No arquivo `src/services/api.ts`, configure o interceptor de resposta (`api.interceptors.response.use()`) para tratar a rejeição de promessas (bloco de erro).

2. **Extração do Padrão de Erro da ServeRest**:
   - A API da ServeRest retorna erros no formato JSON contendo a propriedade `message` (ex: `{ "message": "Email e/ou senha inválidos" }`).
   - Extraia a mensagem de erro de `error.response?.data?.message`.
   - Defina uma mensagem genérica de fallback (ex: `"Ocorreu um erro ao se comunicar com o servidor."`) caso `error.response` ou `data.message` não esteja disponível (erros de rede ou servidor off-line).

3. **Exibição da Notificação (Mantine Notifications)**:
   - Utilize a função `notifications.show()` da biblioteca `@mantine/notifications`.
   - Exiba a notificação com cor vermelha (`color: 'red'`), um título adequado (ex: `"Erro na requisição"`) e a mensagem extraída da resposta da API.

4. **Repasse do Erro**:
   - Certifique-se de retornar `Promise.reject(error)` ao final do interceptor para que os componentes chamadores ainda possam tratar regras de negócio locais (como parar spinners ou resetar formulários), se necessário.
```

**Dica: Como Testar e Visualizar a Notificação de Erro**

Para validar se o interceptor global de erros e as notificações do Mantine estão funcionando corretamente com a API da ServeRest, siga os passos de teste abaixo:

1. **Teste via Login Inválido (HTTP 401)**:
   - Acesse a tela de Login (`/login`).
   - Preencha o e-mail com `usuario_fake_123@teste.com` e qualquer senha.
   - Clique em **Entrar**.
   - **Resultado esperado**: A API ServeRest responderá com status `401` e corpo `{"message": "Email e/ou senha inválidos"}`. Uma notificação vermelha do Mantine aparecerá no canto da tela exibindo a mensagem _"Email e/ou senha inválidos"_.

2. **Teste via Erro de Rede ou URL Inválida**:
   - Altere temporariamente a `baseURL` em `api.ts` para uma URL inexistente (ex: `https://serverest-fake-url.dev`).
   - Realize qualquer ação que faça chamada HTTP.
   - **Resultado esperado**: Como não haverá resposta da API (`error.response` é `undefined`), o interceptor disparará a notificação exibindo a mensagem genérica de fallback: _"Ocorreu um erro ao se comunicar com o servidor."_.

### Abstração de Requisições com Custom Hook (`useAsyncData`)

Em requisições HTTP do tipo `GET`, é extremamente comum repetirmos a criação de 3 estados padrão em nossos componentes:

1. `data`: Armazena os dados retornados pela API.
2. `loading`: Indica se a requisição está em andamento.
3. `error`: Captura e armazena eventuais mensagens de erro.

Para evitar repetição de código (boilerplate) em todas as páginas, abstraímos essa lógica em um **custom hook** genérico denominado `useAsyncData` (cujo código-fonte está disponível em `M04/anexos/useAsyncData.ts`).

#### Exemplo de Uso no Componente

```typescript
import { api } from '../services/api';
import { useAsyncData } from '../hooks/useAsyncData';
import type { Produto } from '../schemas/produto';

export const Produtos = () => {
  const { data, loading, error, refetch } = useAsyncData(async () => {
    const response = await api.get('/produtos');
    return response.data.produtos as Produto[];
  });

  if (loading) return <p>Carregando...</p>;
  if (error) return <p>Erro: {error}</p>;

  return (
    <ul>
      {data?.map((produto) => (
        <li key={produto._id}>{produto.nome}</li>
      ))}
    </ul>
  );
};
```
